## 三层探针设计原则

### 结构级（P-CODE-001 ~ 005）
- **确定性布尔**：结果只有PASS/FAIL，无模糊地带
- **不可绕过**：基于哈希链、签名、引用关系等结构性约束
- **零误报**：只要触发就一定是问题（除已知漏报面）

### 语义级（P-CODE-006 ~ 010 + HALLUC-001/002/004）
- **AST模式匹配**：基于抽象语法树的模式识别
- **低误报**：经过严格的模式过滤，误报率<5%
- **可解释**：每个发现都能定位到具体代码行和模式

### 行为级（P-CODE-011 ~ 014 + HALLUC-003/005/006）
- **统计信号**：基于代码统计特征的风险信号
- **不拦截**：仅用于风险提示和λ调度，不直接阻断交付
- **可校准**：阈值可根据项目特点调整

## 探针执行顺序

```
1. 结构级探针（P-CODE-001~005）
   ↓ 任何FAIL → 直接阻断，不进入后续审计
2. 语义级探针（P-CODE-006~010 + HALLUC-001/002/004）
   ↓ P0发现 → 阻断；P1/P2发现 → 记录并继续
3. 行为级探针（P-CODE-011~014 + HALLUC-003/005/006）
   ↓ 统计信号 → 用于D-S λ调度，不阻断
4. 汇总裁决 → PASS/FAIL + 缺陷位置 + 方言指纹
```

## 强制执行规则（R-CM-1 ~ R-CM-10）

| 规则编号 | 规则内容 | 违反后果 |
|---------|---------|---------|
| R-CM-1 | πₛ必须在实体诞生时分配，禁止跳号/复用 | F探针FAIL，退回重写 |
| R-CM-2 | 接口必须先于实现LOCKED（契约先行） | F探针FAIL，退回重写 |
| R-CM-3 | 跨模型引用必须指向LOCKED实体 | F探针FAIL，退回重写 |
| R-CM-4 | Trae整合产物必须过M-E-F全链路 | F探针FAIL，退回重写 |

| R-CM-6 | D-S只调λ，不参与单轮放行 | F探针FAIL，退回重写 |

## 诚实边界

1. 本探针清单为确定性规则检测，语义级深审（如复杂隐喻、跨模块架构合理性）仍需人工或LLM配合
2. 行为级探针仅为统计信号，不直接判定代码质量，需结合上下文判断
3. AI幻觉检测为启发式规则，可能存在误报（如合法的接口方法、计划中的TODO）
4. 模型方言指纹库基于训练数据特征推断，实际指纹需实测标定
5. 探针不替代CLE（cle-code-probe）的缺陷检测，两者互补使用
